# define-schema

`@idp/artifact-schema` is the **public contract** between the discovery agent, the replay engine, the
operator, and any calling AI agent (R2.7). It is a focal point of the evaluation. Changes here are
deliberate, versioned and fixture-backed.

> The package's `CLAUDE.md` is the authority on file layout. If it disagrees with a path below, follow the
> `CLAUDE.md`. The first schema that lands (the `artifact-schema` spec) becomes the exemplar. Once it exists,
> **read it and copy its shape.**

## Hard rules

- **Schema + type side by side.** `export const <Name>Schema = z.object({...})` and
  `export type <Name> = z.infer<typeof <Name>Schema>`, in one file per concept.
- **Discriminated unions carry `kind`.** Steps, locator rungs, checkpoints, outcome rules and `RunResult` are
  unions on `kind`. Never use optional-field soup.
- **Every field is documented** with `.describe('…')`. The description ships in the JSON Schema, and it is
  how a calling agent and a human reviewer learn what the field means (R2.7). Robustness reasoning for
  locators goes in the description too (R2.3).
- **No sensitive values in the contract.** Values that come from parameters are templates (`{{memberId}}`),
  and fields that may hold observed data are typed so the redaction layer can find them. Never add a field
  that stores a raw credential or a full PII value.
- **Strict objects** (`.strict()`) for persisted artifacts, so typos fail loudly on load.
- **Runtime dep is `zod` only.** No Playwright or Node-only types leak into the contract. The contract must
  describe a desktop surface as easily as a web one (R7.1). Surface-specific details live under a
  surface-tagged sub-object, never in the core step shape.
- **Versioning.** The artifact carries `schemaVersion` (semver of the contract):
    - patch: docs or descriptions only.
    - minor: a new optional field or a new union member that old engines can reject cleanly.
    - major: a removed or renamed field, a changed meaning, or a newly required field. Add a migration note
      to the package `CHANGELOG.md`.

## Steps

1. Read the package `CLAUDE.md`, the existing schemas, and the spec/plan bullet for this change.
2. **Test first.** In `<Name>.test.ts`, write valid fixtures that parse, and invalid fixtures (missing
   required field, wrong `kind`, unknown extra key on a strict object, a raw secret where a template is
   expected) that fail with a useful path. Run `pnpm --filter @idp/artifact-schema test -- <Name>` and confirm
   it is red.
3. Implement the schema. Export it from the barrel.
4. Register it in the JSON Schema export (the package's generator script/module, e.g. `z.toJSONSchema`),
   regenerate the committed `schemas/*.json`, and check the diff is what you intended.
5. Update the example artifact fixture(s) under the package's `fixtures/` so they validate. If the fixture
   in `evidence/` is affected, note it in the report. Evidence is regenerated by `/capture-evidence`, never
   hand-edited.
6. Bump `schemaVersion` per the rules above, and add a `CHANGELOG.md` line.
7. `pnpm --filter @idp/artifact-schema build && pnpm --filter @idp/artifact-schema test`, then build the
   dependents (`pnpm build`) to catch consumers broken by the change.
8. Report:
   ```
   Schema:   <Name> (<file>)
   Change:   add | change — <summary>
   Version:  <old> → <new> (<patch|minor|major>: why)
   Fixtures: <updated files>
   Consumers affected: <packages that needed changes, or none>
   ```
