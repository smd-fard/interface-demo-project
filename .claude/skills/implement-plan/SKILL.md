# implement-plan

The orchestrator. It reads `_design/<slug>/plan.md`, derives a task graph, embeds the relevant `SKILL.md` (and
its `references/*`) into each spawned agent's prompt, enforces the phase order with verification gates, and
emits a report. **The main agent never writes production code.** It writes only the glue edits (listed below)
and `_design/index.md`.

## Args

`<feature-slug>`. `_design/<slug>/plan.md` must exist (generated by `/define-plan`).

## Hard rules

- **Orchestrate, never implement.** Production files are written by subagents.
- **Phase order is non-negotiable.** Phase N starts only after Phase N−1's gate passes.
- **Parallel only on disjoint files.** Tasks that share a file (a barrel `index.ts`, the action registry,
  `mock-bank`'s router, the condition catalog) run sequentially.
- **Embed, don't delegate.** Subagents have no Skill tool. Paste the full `SKILL.md` + every file it references.
- **Gates are hard stops.** On failure: halt, report verbatim, list done and remaining tasks. **No silent retry.**
- **Idempotent.** Skip a task whose primary output file already exists and report it as "already done".
- **TDD where the skill says so.** The prompt must require red → green and forbid relaxing a test to pass.
- **No real LLM in tests.** If any agent reaches for a real model or network call in a test, halt.

## Plan → skill mapping

| Plan step language                                              | Skill                       | Parallel?                                     |
| --------------------------------------------------------------- | --------------------------- | --------------------------------------------- |
| "Scaffold `packages/<n>`" / "Scaffold `apps/<n>`"               | `scaffold-package`          | Yes across packages (distinct dirs); glue edit to `pnpm-workspace.yaml` done by main agent after |
| Zod contract / schema / "RunResult" / artifact field            | `define-schema`             | No — shared barrel + JSON Schema export        |
| New action type (click, fill, select, extract, navigate, …)     | `define-action`             | No — touches schema, policy, surface, replay, agent registries |
| Runtime condition (not found, validation, dialog, timeout, …)   | `define-runtime-condition`  | No — shared condition catalog + mock-bank faults |
| Mock-bank page / flow / fault switch / tenant variant           | `define-mock-screen`        | No — shared router                              |
| Unit tests for an existing file                                 | `write-unit-test`           | Yes — disjoint files                            |
| Functional test (replay/agent/session against mock-bank)        | `write-functional-test`     | Yes if distinct files                           |
| Engine logic without a generator (lease state machine, compiler, loop) | TDD (generic prompt below) | No within a package                           |
| CLAUDE.md / README / TSDoc                                      | `update-docs`               | Yes — disjoint packages                         |
| `pnpm-workspace.yaml`, root `package.json` scripts, `turbo.json`, `tsconfig` references | glue (main agent) | Sequential                                  |

**Generic TDD prompt** (no generator skill): "Write the test file first. Run
`pnpm --filter <pkg> test -- <File>` and confirm it fails for the right reason. Implement until green. Keep to
the package's CLAUDE.md and the root Hard invariants. Do not modify tests to make them pass."

## Steps

### 0. Preconditions

- `git status --porcelain` is clean, or contains only `_design/` / `docs/adr/` files.
- Branch is `feature/<slug>`. Warn and confirm on any other branch.
- `plan.md` and `spec.md` exist. The plan's **Open items** do not block implementation (only the spec's Open
  Questions would, and `/define-plan` already refused those).

### 1. Parse → task graph

Read `plan.md` + `spec.md` in full. From every bullet under each Implementation step, derive: task type (skill,
TDD or glue), args, primary output file, phase (1–7, as in the plan), and parallelism. Check idempotency.

Print the graph and **wait for the user's "go"**:

```
Phase 2 — Contracts
  T3  define-schema CapabilityArtifact       [primary: packages/artifact-schema/src/artifact/CapabilityArtifact.ts]
  T4  define-schema RunResult                [sequential after T3]
  GATE: pnpm --filter @idp/artifact-schema build && pnpm --filter @idp/artifact-schema test
```

### 2. Cache skill content

For each skill in the graph, read `.claude/skills/<skill>/SKILL.md` and every file it references
(`references/*`, and the exemplar files it names). Keep them for embedding.

### 3. Execute phases

For each phase, spawn one Agent per task (in parallel only where the table allows). Prompt shape:

```
[TASK]
You are implementing part of feature <slug> in the interface-demo-project monorepo at <repo-root>.
Your single task: <skill> <args>   (or: TDD — <description>)

[PROJECT RULES]
<root CLAUDE.md sections: Workspace map, Dependency direction, Hard invariants, Conventions>
<the target package's CLAUDE.md, if it exists>

[SKILL INSTRUCTIONS — execute exactly]
<full SKILL.md>

[REFERENCES]
### <path>
<full contents>  (every referenced file)

[DOMAIN CONTEXT — from _design/<slug>/plan.md]
<the plan bullet(s) for this task, verbatim, plus relevant spec ACs>

[COMPLETION PROTOCOL]
Success: print "AGENT_SUCCESS: <task>" then a list of files created/modified.
Failure: print "AGENT_FAILURE: <details>" and stop.
Do not run the phase gate; the orchestrator does it. Do not commit.
```

Glue tasks (the main agent does these directly, after the phase's agents finish): add workspace entries,
root scripts, tsconfig references, then `pnpm install`.

### 4. Gates (after each phase)

```bash
pnpm install          # if package.json files changed
pnpm --filter <each touched package>... build
pnpm --filter <each touched package>... test
```

For the final phase, or when unsure, run the root `pnpm build && pnpm test`. A red gate means halt. Before
reporting a functional-test failure, re-run that package in isolation once, so that a port or process
collision is not reported as a defect. Report only a failure that reproduces.

### 5. Safety + docs

- Run the checks from `.claude/commands/safety-review.md` against the branch diff (embed that file in a
  read-only subagent, or run it in the main agent). **Any `block` finding halts the run.**
- Run `update-docs` for every touched package (in parallel).
- If the plan changed the artifact contract, confirm the JSON Schema export and the fixtures were regenerated.

### 6. Full verification + report

`pnpm build && pnpm test`, then the plan's Verification smoke commands. Update `_design/index.md` Status to
`In progress` (the user sets `Shipped` after merging). Report:

```
Feature:      <slug>  (branch <branch>)
Plan:         _design/<slug>/plan.md
Phases:       1 ✓ scaffolds (<n>) | 2 ✓ contracts (<n>) | 3 ✓ core | 4 ✓ surface/target | 5 ✓ engines | 6 ✓ apps | 7 ✓ docs
Skipped:      <already-done tasks>
Safety:       PASS | findings
Verification: build ✓ | tests ✓ (<n> files) | smoke ✓
Open items:   <copied from plan>
Next:         /commit → merge feature/<slug> into main (--no-ff) → /trace-requirements
```

## Failure report

```
ORCHESTRATION HALTED
Phase: <N — name>   Task: <task> <args>
Error:
<verbatim output>
Completed: ✓ …
Remaining: · …
To resume: fix the issue, then re-run implement-plan <slug> (completed tasks are skipped).
```
